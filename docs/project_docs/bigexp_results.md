# bigexp 대규모 실험 결과와 외부 저장소 검토 (2026-11-04, 같은 날 재감사로 정정)

champ_fix_log.md(이전 단계)의 후속 기록. 이전 문서에는 아래 내용이 없다: sym_audit 결과, 시작 시 뒤집힘 메커니즘, 대규모 실험(P0~P5), 외부 저장소 검토, 재감사 정정.

## 정적 감사 결과 (sym_audit.py, 2026-11-04)
- URDF 다리별 값(축/한계/댐핑/마찰/원점/질량/관성/충돌/접촉)은 4다리 대칭이고 원본 URDF와 diff 0건. config/joints.yaml, links.yaml 매핑도 올바름. -> "다리별 설정 오류" 가설 기각. 비대칭은 구조적(무릎 뒤, CoM 약 1.1 cm 후방, 후방 하중 약 53%).
- CHAMP(ros2 브랜치)와 libchamp 소스 검토: 보행 생성(phase_generator, trajectory_planner, leg_controller)은 속도 부호에 대해 대칭이다. 후진은 궤적을 pi 회전할 뿐이고 라이베르트 발 위치(stance_duration/2 * v), 12점 베지어 스윙, 직선 스탠스가 부호와 무관. 우리 launch는 cmd_vel/smooth를 cmd_vel로 리매핑해 속도 스무더도 없다. -> 전진/후진 차이는 코드 비대칭이 아니라 플랜트(기하, 접촉, 질량 분포, 오픈루프)에서 와야 한다.

## 시작 시 뒤집힘의 메커니즘 (posture/posture2/posture3)
- 컨트롤러 활성화(약 0.3~1 s) 전에 다리가 풀려 thigh 1.11 / calf -2.70(관절 한계)로 접힘(z 약 0.10). 활성화 순간 PD가 목표 자세로 끌어올려 몸통이 튐(z 0.44~0.48, pitch -27°~-82°, roll ±180°).
- 튀는 크기는 목표 높이에 비례: calf 변화 0.6 rad(h 0.20, 생존) / 0.85(0.24, 뒤집힘) / 1.11(0.28, 뒤집힘). 스폰 높이는 원인이 아니다.
- 해결: pi2.py relay를 "내부 명령값을 일정 속도(1 rad/s)로 전진"하도록 수정(fix_pi2c.py). 이전 판은 명령을 '측정값+작은 증분'으로 만들어 몸이 눌린 상태에서 토크가 안 나와 기립하지 못했음. 수정 후 0.24 m가 2.4 s에 z 0.25로 기립. 0.20 대조군에서 릴레이는 걷기 결과에 중립(0.22 / 0.92 / 0.56 / 0.61).

## 대규모 실험 (bigexp.py: DOE + 중첩 sweep, 2026-11-04 오후, 결과 ~/bigexp/results)
설계: 변수 p, d(=km*0.9*sqrt(p/360)), com_x, nominal_height. 나머지 전부 기준선 고정. 모든 조건 소프트 스타트, 조건마다 새 시뮬. 시험 walk/back 2회씩, 목적함수 obj = min(walk, back 전진비).
- P0 기준선 5회: walk 0.19~0.21, back 0.90~0.96, sigma(obj)=0.020 (재현성 좋음), 방향 -15°. 시뮬이 거의 결정적이라 sigma 0.02는 모델 오차가 아니라 거의 순수 시뮬 잡음 하한.
- P1 2^4 완전요인+중심점: 16개 코너 전부 기준선(0.21)보다 나쁨(최고 0.19). 코너 다수가 방향 -70°~-98°로 불안정. 효과표는 모델이 포화(11모수/16점)+곡률 큼(중심점 0.122 vs 요인평균 0.030)이라 신뢰 낮음.
- P2 p(30~1600) x km(0.4/1/2.5) + 역순 재현: 최고 0.22 (p340, km1, 즉 기준선 부근). 저강성(p<=100, d<=0.9)은 음수 walk, 고강성(p>=750)은 이득 a가 0.2로 하락. p-d 평면에 기준선보다 나은 영역 없음.
- P3 com_x{-0.09..0.03} x 높이{0.20,0.22,0.24} @ p340: 안정적 최고 0.26 (cx -0.03/-0.06, h 0.22). cx -0.09는 방향이 -71°~-206°로 붕괴(walk 0.73이 나왔지만 회전하며 이동한 값 -> 무효).
- P5 확증(5회씩): 기준선 0.22 / 0.92~0.93 대 최고 설정(p340, d0.875, cx -0.03, h0.22) 0.23~0.26 / 1.08 -> walk +0.03 (재현되나 실용적으로 미미). 목표 0.7과 큰 차이.
- P4 속도 응답(기준선): fwd 0.05/0.1/0.2/0.3/0.4 -> -0.027/+0.002/+0.045/+0.069/+0.074, bwd -> -0.097/-0.123/-0.189/-0.272/-0.341 m/s. 작은 명령 적합 v ~ -0.06 + 0.7*cmd. 전진은 cmd 0.1 이상에서 포화(순 +0.07 m/s 부근), 후진은 0.3~0.4까지 선형.

### 정정 (재감사): "편향이 이득에 비례" 주장 철회
- 이전 판에 "안정 조건 69개에서 b = -0.094*a - 0.024 (상관 -0.70), 편향이 이득에 비례"라고 적었으나 **산술 부산물**이다. a = 0.5(walk+back), b = 0.1(walk-back)이고 walk가 거의 상수(<=0.26)이면 a, b가 같은 back 변동의 +/- 이므로 기계적으로 역상관된다. walk를 상수로 두고 back만 섞은 귀무 모형 상관이 -0.65, 관측 -0.70 -> 정보 없음.
- 실제로 말할 수 있는 것: (1) 모든 안정 조건(n=80, |방향|<45°)에서 walk <= 0.26 (p, d, 높이, cx -0.06~0.03 전부), 같은 조건에서 back은 0.1~1.14로 변함. walk와 back의 상관 0.67. (2) 작은 명령 적합에서 걸음이 켜진 상태의 후방 오프셋 약 -0.06 m/s (포화가 아니라 오프셋). (3) 음수 walk 값은 "걸음이 안 나왔다"가 아니라 전진 명령인데 몸통이 뒤로(또는 옆으로 돌며) 이동했다는 뜻. 다리는 움직이고 있음.
- 지표 유효성 주의: 변위 투영 지표는 방향이 크게(>45°) 돌면 무효. 구 gait_eval의 speed_ratio는 |변위| 기반이라 부호를 못 봄. 추종비 절대값은 이전 측정과 불일치(추종비 1.0이 이득 불변이라는 근거는 약함). p와 서 있는 높이(처짐)는 교란되어 있음.
- com_x는 편향을 움직이는 유일한 변수(cx -0.09에서 b 약 +0.079) 하지만 방향 안정성이 -0.06과 -0.09 사이에서 무너짐. cx -0.06, h0.20이 가장 곧은 조건(방향 -0.7°, walk 0.26, back 0.85).

### 후보 판정 (CHAMP 쪽)
- 기각: 마찰, 스윙, 발 끌림, PD 게인(추종 개선해도 walk 불변), 솔버, 접촉 강성, 자세 높이(0.20~0.24), 보행 생성기 명령(명령 진폭 전후 대칭 1.00~1.13), 다리별 설정/URDF 비대칭, 보행 코드의 부호 비대칭.
- 남음: 기하/접촉 비대칭(발 들림 전진 1.6~2.2 cm vs 후진 1.8~4.1 cm, 명령 4 cm) + 오픈루프(CoM 후방). com_x -0.06~-0.09 사이 미세 구간(P6)은 진행 예정.

## 외부 저장소 검토 (2026-11-04)
- mayataka/unitree_ros2 (마지막 커밋 2022-09-14): ros2_control + 자체 gazebo 시스템 플러그인(위치/속도/effort/Kp/Kd 명령 인터페이스, tau = tau_ff + Kp(q*-q) + Kd(dq*-dq), +-33.5 제한). 컨트롤러는 ZeroTorque/StandUp(Kp20, Kd10)/SitDown 모드뿐, 보행 코드 없음. A1 URDF는 chvmp/unitree_ros와 같은 값(thigh/calf 0.2 m, 발 반경 0.02, 몸통 6 kg). 코드에 문법 오류(create_service()<...>)가 있어 그대로는 빌드 안 될 가능성(직접 빌드는 안 해 봄). 구 unitree_ros 게인(hip 100/5, thigh·calf 300/8) 참고만 가능.
- crystaldust/unitree_a1_ros2: 실물 A1용 SDK 드라이버(HighState 노출). 시뮬 없음, 보행 개선과 무관.
- 결론: 두 저장소 모두 우리 문제의 해법이 아님.
