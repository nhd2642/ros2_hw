# CHAMP 직접 수정 트랙 (2026-11-04 오후)

결정: rl_sar로 같은 PC에서 A1이 전진 보행하는 것을 확인했으므로(환경은 정상) CHAMP 쪽 원인을 시간을 정해 찾는다. rl_sar는 대안/비교 기준선으로 유지. (gait_experiment_log.md, gait_alternatives_research.md 참고)

## 업스트림 CHAMP 코드 확인 (chvmp/champ ros2, quadruped_controller.cpp)
- 관절 위치만 담은 점 1개(속도/가속도 없음), time_from_start = 1/60 s, 200 Hz 벽시계 타이머. 발 접촉 정보 미사용.

## P1: command interface effort -> position — 폐기 (판정 불가)
- gazebo_ros2_control(humble): position이면 매 스텝 SetPosition+SetVelocity(0). 명령 초기값은 command_interface의 initial_value에서만.
- 컨트롤러 활성화 전 다리가 접혀 있다가 활성화 순간 서는 자세로 순간이동 -> 몸통이 튕겨 올라 뒤집힘. 소프트 스타트 릴레이로 뒤집힘은 해결했지만, 몸이 땅에 닿은 상태에서는 관절이 명령을 못 따름(실제 thigh 1.21/calf -2.58 vs 명령 1.05/-2.09, z 0.05 고정). 부하가 걸린 다리에서는 이상적 강체 관절이 아님.

## T1: 릴레이로 time_from_start/속도만 변경 (effort 경로 유지) — 부분 결과
- ctrl(1/60 s 그대로 통과): walk 0.22 / back 0.92 / spin_L 0.57 / spin_R 0.61 = 기준선과 같음 -> 릴레이 자체는 중립.
- tfs5(5 ms), tfs5v(5 ms+속도): 시작 직후 뒤집혀(z 0.06, 기울기 180°) 시험 불가. 1/60 s의 느린 응답이 시작 때 완충 역할을 한다는 정도만 알 수 있음. 걸음 판정은 못 함.
- 그리고 이 가설(제어 경로/궤적 지연)은 전진/후진 모두에 똑같이 작용해서 비대칭을 설명하기 어렵다 -> 우선순위 하향.

## 기록을 다시 읽고 얻은 핵심: 증상은 비대칭인데 바꾼 값은 전부 대칭이었다
증상(모두 기록에 있음):
- 전진 0.21 vs 후진 0.97 (같은 명령 크기)
- 전진 시 시계 방향 쏠림 -25~-38° (초기 기준선)
- spin 우회전이 좌회전보다 큼(우/좌 1.1~1.7), 제자리가 아님(이동 0.35~0.6 m)
- 다리별 착지 훑기 속도(몸통 기준 x, 이상 -0.2): 전진 FL -0.05 / FR -0.14 / RL -0.12 / RR +0.17; 후진 FL +0.17 / FR +0.37 / RL +0.28 / RR +0.05 (대각선 FL+RR 쌍이 약하거나 역방향. 단, z 기준 착지 분류는 잡음 가능)
- 뒷다리 종아리 추종 RMS가 앞다리의 약 1.5배(RL 0.121, RR 0.105 vs FL 0.073, FR 0.076), 진폭비 RL 0.74 / RR 0.65 / FL 0.95 / FR 0.91
- 명령이 0인 hip이 0.07~0.09 rad 흔들림, 허벅지 진폭비 1.1~1.5(명령보다 크게 움직임)
- com_x를 바꾸면 전진과 후진이 맞바뀜(제로섬)
지금까지 바꾼 34조합과 개별 실험(게인, 마찰, 스윙, 주기, com_x 제외, 솔버, 접촉)은 모두 네 다리에 똑같이 적용되는 값. 비대칭 증상의 원인은 다리마다 다른 요소(URDF 다리별 값, CHAMP의 links/joints 매핑, 손으로 만든 yaml)에 있을 가능성이 높고, 그 부분은 한 번도 점검하지 않았다.
- 점검 안 한 것: config/links.yaml, config/joints.yaml (패키지 가이드: CHAMP가 A1용 ROS 2 설정을 제공하지 않아 직접 만든 파일), URDF는 원본을 변환 후 손으로 수정함(make_a1_urdf.py 결과와 다름).
