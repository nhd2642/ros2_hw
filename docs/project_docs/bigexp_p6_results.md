## 해석
1. **cx -0.065 ~ -0.070 사이에 체제 전환(분기)이 있다.** 두 높이 모두에서 이 구간을 넘으면 (a) 전진 경로 전진비가 0.3 -> 0.5 이상(h0.22는 0.8~1.07)으로 뛰고, (b) back 시험이 후진하지 못하고 방향이 -166~-251도 도는 것으로 바뀐다. 매끄러운 변화가 아니라 문턱 현상.
2. **신 영역에서는 명령 부호와 무관하게 앞으로 밀리고 시계방향(-)으로 돈다.** h0.20에서 bwd0.05(후진 명령)가 +0.03 m/s로 앞으로 간다(b05 > 0). walk와 back 둘 다 방향이 음수. 구 영역에서는 방향이 작고 부호가 섞여 있었다. 서 있을 때(idle)는 표류가 없으므로 걸음이 켜졌을 때만 생기는 편향(전진 + 요 편향)이다.
3. **전진 목표 속도는 신 영역에서 처음 도달 가능**: h0.20 cx -0.07~-0.08은 방향이 유효(-20~-35도)한 채 경로 전진비 0.49~0.55, h0.22 cx <= -0.07은 몸통 기준 전진 속도가 0.78~1.07배(단 10초에 -93~-151도 회전하며 원을 그림). 이전 결론 "모든 조건에서 walk <= 0.26"은 cx >= -0.06 구간에서만 성립했다.
4. **동시 달성은 안 된다.** 어느 칸도 (속도비 >= 0.7, 방향 오차 <= 15도, back 정상)를 동시에 만족하지 못함. cx를 전진에 맞추면 후진이 죽고, 후진에 맞추면(cx 0 ~ -0.06) 전진이 0.26에 막힌다. 정적 com_x 하나로는 부호가 반대인 두 요구를 모두 못 채운다.
5. **작은 명령 선형 모델은 전환 근처에서 틀린다.** cx -0.065 h0.20: f05/b05로 구한 이득 0.72, 편향 +0.015 이면 walk 0.2에서 약 0.8배가 나와야 하는데 실측 0.29. 전진 속도가 명령에 따라 늘지 않고 포화(전진 상한 약 0.06~0.11 m/s, cx가 작을수록 약간 높음)하기 때문.

## 신뢰도 주의
- 방향이 돌아간 칸(h0.22 cx <= -0.07, h0.20 cx <= -0.075의 back)에서 f05/b05/편향/이득은 초기 방향 투영이라 오염. 이 칸의 편향 수치는 쓰지 말 것. 방향 값(hdg)과 경로 전진비만 신뢰.
- walk/back 각 2회 평균이고, '*'는 2회 중 하나라도 45도 초과. 시뮬이 거의 결정적이라 반복 변동은 작지만 전환 구간 경계(-0.065)에서는 한 칸 차이로 결과가 갈릴 수 있음.
- 메커니즘(왜 -0.065에서 전환, 왜 시계방향)은 아직 가설일 뿐 측정하지 않았다. 후보: 발 위치가 뒤로 밀리며 다리별 하중 분배 변화, 대각 발 쌍의 시작 위상 비대칭, 발 미끄러짐.

## 진단 A 1차 시도 (2026-11-04 18:20): 실패, 원인 확인

1. **joint_states에 effort가 없다** (토크 있음 False). ros2_control state interface에 effort가 노출되지 않았거나 JSB가 싣지 않는 것으로 보임(원인 확인 필요: ros2_control URDF 블록의 state_interface 목록).
2. **표본이 약 10 Hz뿐이었다** (27 s에 270개). 평가 노드가 시간을 콜백 처리 시점의 now()로 재서, 한 번에 몰려 처리되는 메시지가 같은 시각으로 찍혀 4 ms 간격 필터가 50 ms 당 1개만 통과시킨 것. **bigexp.py의 ev()도 같은 구조**(put(), gap 0.004, now()) 라서, 대규모 실험의 추종비(tracking) 진단은 10 Hz 표본으로 계산됐을 가능성이 높다 -> "추종비 절대값이 이전 측정과 안 맞는다"는 불일치의 유력한 원인이며, "PD 추종은 원인이 아니다"라는 근거는 그만큼 약하다. (몸통 속도/방향 지표는 ground_truth odom 의 시작/끝 값과 경로 적분이라 영향 없음. 실제로 diag6 의 v_path 가 P6 값과 일치: cx 0 walk 0.043 m/s = 0.21배, back -0.194 = 0.97배.)
수정: header 시각 사용 + 별도 스레드 실행기 + effort 없으면 PD 명령 기반 토크 추정(p*(q_cmd-q) - d*qdot, 서 있을 때 체중으로 배율 보정, 한계: 보정 배율 하나로 동적 오차 흡수).
